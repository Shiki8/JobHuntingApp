# compare-flow

## Overview

比較したい求人を求人一覧で選択し、比較画面で基本情報を横断的に確認・検討するフロー。求人一覧のチェックボックス操作から始まり、基本情報テーブルでの確認・除外・評価遷移までを対象とする。

## Actors

- **ユーザー**: 転職候補の求人を複数選択して条件を比較し、次のアクション（評価入力・除外・応募検討）を決める

## Flow

1. ユーザーが求人一覧（`/`）を開き、比較したい求人のチェックボックスを2件以上オンにする
2. `useCompareStore.selectedIds` に選択した求人 ID が追加される
3. ユーザーがサイドバーまたはヘッダの「比較」リンクをクリックして `/compare` に遷移する
4. Compare ページが `useCompareStore.selectedIds` と `useJobStore.jobs` を突合し、選択中の `Job` オブジェクトの配列を生成する
5. 2件以上の場合、基本情報テーブルが描画される
   - 左固定列：会社名・職種・応募ステータスバッジ
   - スクロール列：勤務地→年収→始業時間→リモート可否→年間賞与→年末年始休暇→住宅補助→雇用形態→必須スキル→技術スタック→媒体→気になる点
6. ユーザーがテーブルを横スクロールして各項目を確認する
7. 比較を終えたユーザーは次のいずれかの操作に進む

   a. **詳細確認**: 左固定列の会社名をクリックして `/jobs/:id` に遷移する  
   b. **評価入力**: 当該求人の評価画面（`/jobs/:id/score`）に遷移する  
   c. **比較から除外**: 「×」ボタンで対象求人を `useCompareStore` から削除する（2件未満になれば空状態に切り替わる）  
   d. **全選択解除**: ヘッダの「選択をクリア」ボタンで `useCompareStore.clear()` を呼び出す

8. ユーザーが「← 戻る」ボタンをクリックすると求人一覧（`/`）に戻る

## Edge Cases

- **比較対象が2件未満（0件・1件）**: テーブルは描画されず `EmptyState` を表示する。ページ自体はリダイレクトしない。「求人一覧に戻る」ボタンのみ提供する
- **選択済み ID に対応する Job が存在しない**: `jobs.find()` の結果が `undefined` になるため `filter(Boolean)` で除外される。テーブルには表示されない
- **スキル系フィールドが4件以上**: 先頭3件のみタグ表示し、残り件数を `+N` で省略する
- **年収が片方のみ設定**: `salaryMin` のみ → `最小万〜`、`salaryMax` のみ → `〜最大万` で表示する
- **媒体が「その他」で sourceNote あり**: `その他: {sourceNote}` の形式で表示する
- **住宅補助フィールドが未設定（false）**: `—` を表示する。`true` のみ `✓` を表示する
- **気になる点が長文**: `line-clamp-4` で4行に切り詰め、最小幅 200px・最大幅 240px のセルに収める
