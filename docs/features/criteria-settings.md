# criteria-settings

## Overview

求人を比較するときの評価観点（評価軸）を管理する画面。評価軸ごとに名前・重み（0〜5）・説明をインライン編集でき、ドラッグ＆ドロップで表示順を変更できる。重みは合致度スコアの計算に直接影響する。

## Background

求人の比較軸はユーザーごとに異なる（年収重視か技術重視か、など）ため、評価軸そのものをユーザーが自由に定義できる設計にした。一方で新規ユーザーが最初から白紙では使いにくいため、初回マウント時にデフォルト6軸を自動投入する。

合致度スコアの算出式は `round(Σ(score × weight) / Σ(weight × 5) × 100)` であり、weight=0 の軸はスコア分母に算入されない。これを利用して「今回の転職活動では重視しないが設定は残したい」軸を weight=0 にすることで参考記録として保持できる。

削除時の Score 連鎖削除をストア内部で自動実行しない理由は、`useCriteriaStore` と `useScoreStore` を直接依存させると双方のストアを変更するたびに影響範囲が広がり、テスト・再利用が難しくなるためである。ストアは自身のエンティティのみを操作し、連鎖削除はユーザーの明示的な操作に対応する UI 側（`CriteriaSettings.tsx`）が担う。

## User Stories

1. デフォルト6軸が最初から入っているので、アプリを開いてすぐ求人を評価できる
2. 自分の転職軸に合わせて評価軸の名前・重み・説明を変更したい
3. 不要な評価軸を削除したい。削除前に「何件の評価が消えるか」を確認したい
4. 今回の転職では重視しないが設定は消したくない軸を weight=0 にして対象外にしたい
5. 評価軸の並び順を直感的にドラッグ＆ドロップで変えたい
6. 現在の評価軸が合致度スコアに与える最大値（重み合計）を確認したい

## Behavior

### デフォルト6軸の自動投入

- `Layout.tsx` の `useEffect` 内で `useCriteriaStore.initDefaults()` を呼び出す
- `initDefaults()` は `criteria` が空のときのみ実行される（既存データを上書きしない）
- デフォルト6軸の内容（`src/types/index.ts` の `DEFAULT_CRITERIA`）：

| 名前 | 重み | 説明 |
|---|---|---|
| リモート | 3 | フルリモートなら5、出社必須なら1 |
| 年収 | 5 | 希望年収レンジに対して達成度を評価 |
| 技術スタック | 4 | 自分の強みと学びたい技術に合っているか |
| 裁量 | 3 | 設計・意思決定への関与度 |
| カルチャー | 3 | 企業文化・働き方が自分に合うか |
| 成長環境 | 4 | 学習機会・メンバーのレベル |

### 評価軸一覧表示

- `criteria.order` 昇順でソートして表示
- 各行に「ドラッグハンドル / 名前 / 重みセレクタ / 説明 / 削除ボタン」を並べる
- 削除ボタンは行ホバー時のみ表示（`group-hover` で制御）

### インライン編集

- 名前・説明は `<input>` のフォーカス時にアンダーラインが表示される編集 UI
- 重みは 0〜5 のボタンをクリックして選択。選択中の値は青くハイライト
- 変更は即時 `updateCriteria(id, patch)` を呼び出して localStorage と Supabase に反映される（確認ダイアログなし）

### weight=0 の「対象外」ラベル

- 重みを 0 に設定すると重みセレクタの右に「対象外」バッジが表示される
- weight=0 の軸は合致度スコアの分母に算入されない（参考記録モード）
- 採点画面（`/jobs/:id/score`）には引き続き表示され、スコアを入力できる

### ドラッグ＆ドロップ並び替え

- `@dnd-kit/core` の `DndContext` + `SortableContext`（`verticalListSortingStrategy`）で実装
- センサーは `PointerSensor`（マウス・タッチ）と `KeyboardSensor`（キーボード操作）の両方を登録
- ドラッグ中の行は `opacity: 0.5` + `shadow-lg` で視覚的に浮き上がる
- ドラッグ完了時に `reorder(orderedIds)` を呼び出し、全行の `order` フィールドを連番で更新する

### 評価軸の追加

- 「評価軸を追加」ボタンで空の行を末尾に追加（`name: '', weight: 3, description: ''` の初期値）
- 評価軸が0件のときは EmptyState を表示し、そこにも追加ボタンを配置

### 評価軸の削除

削除ボタン押下時のフロー：

1. `useScoreStore.getState().scores` から削除対象の `criteriaId` を持つ Score 件数を集計する
2. `ConfirmModal` を表示
   - Score が 1 件以上ある場合：「`{軸名}` を削除します。この軸に入力した評価が `{N}` 件削除されます。」
   - Score が 0 件の場合：「`{軸名}` を削除します。」
3. ユーザーが「削除する」を選択すると以下を順に実行：
   1. `deleteScoresByCriteria(criteriaId)` — 対象 Score をすべて削除
   2. `deleteCriteria(id)` — 評価軸を削除
4. 削除後に残りの軸の `order` は 0 から連番で振り直される

**連鎖削除を UI 側で担う理由**：ストアは自身のエンティティのみを責務とし、ストア間の直接依存を持たない設計方針による（CLAUDE.md 参照）。

### フッタ統計表示

評価軸リストの末尾に以下の統計を表示する：

- 左側：`{総軸数}軸（スコア対象: {weight > 0 の軸数}軸 / 対象外: {weight === 0 の軸数}軸）`
- 右側：`最大重み合計: {Σ(weight × 5)}点`

「最大重み合計」は全評価軸に満点（5点）をつけたときの合致度スコアの分子であり、スコア計算の上限感を把握するための参考値。

### バリデーション・エッジケース

| 状況 | 動作 |
|---|---|
| 名前が空のまま別の軸を操作 | 制約なし（空名のまま保存される）|
| 全軸を weight=0 にする | 許容。合致度スコアは 0% になる |
| 評価軸を全件削除する | EmptyState を表示。initDefaults は再実行されない（criteria.length > 0 条件を満たさないが、initDefaults は初回マウント時にしか呼ばれない）|
| 削除ダイアログでキャンセル | `deleteTarget` を null にリセットし何も変更しない |
