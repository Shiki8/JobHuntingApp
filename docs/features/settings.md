# settings

## Overview

アプリ全体のデータを管理する画面。現在のデータ件数の確認、JSON によるエクスポート・インポート、全データリセット、スコア計算方式の参照ができる。バックエンドを持たないローカルファーストの設計において、データのバックアップと復元の唯一の手段を提供する。

## Background

このアプリはすべてのデータを localStorage に保存し、サーバーとの同期を持たない（Google OAuth によるクロスデバイス同期は別途実装済みだが、オフライン・スタンドアロン運用もサポートする）。そのため、ブラウザのストレージが消去されるとデータが失われるリスクがある。Settings 画面は、JSON ファイルを用いたポータブルなバックアップ・復元フローを提供することで、このリスクに対処する。

エクスポート形式に `version` フィールドを含めているのは、将来スキーマが変わった際にインポート時のマイグレーション処理を差し込めるようにするためである（現時点では `version: 1` のみ）。

全データリセット後に評価軸6軸が自動投入される理由は `initDefaults()` の設計にある。`initDefaults` は「criteria が空の場合にだけデフォルト6軸を生成する」という冪等な初期化処理であり、リセットで criteria を空にした直後に呼ぶことで、アプリを初回起動状態と同じ使いやすい出発点に戻すことができる。

スコア計算方式は Settings 画面に読み取り専用で表示されている。設定変更の対象ではないが、ユーザーが合致度スコアの意味を理解できるように参照情報として置かれている。

## User Stories

1. ブラウザを変えるときや PC を交換するときに、今まで登録した求人・評価・スコアデータを引き継ぎたい
2. 誤操作で求人データを大量削除してしまったときに、バックアップから復元したい
3. アプリをきれいな状態に戻したいとき、全データを一括削除してデフォルト評価軸だけ残した状態にリセットしたい
4. 合致度スコアが何の数値を表しているか確認したい
5. 現在何件の求人・評価軸・評価が登録されているか一目で把握したい

## Behavior

### データ件数サマリー

- 求人（`useJobStore.jobs.length`）、評価軸（`useCriteriaStore.criteria.length`）、評価（`useScoreStore.scores.length`）の現在件数をリアルタイムで表示する
- 表示は読み取り専用。この画面から件数を直接変更することはできない

### エクスポート

- 「JSONをダウンロード」ボタンを押すと、全ストアのデータを1つの JSON ファイルとしてダウンロードする
- ファイル名: `job-compare-backup-YYYY-MM-DD.json`（実行日の ISO 日付）
- JSON スキーマ:
  ```json
  {
    "version": 1,
    "exportedAt": "<ISO8601文字列>",
    "jobs": [ ... ],
    "criteria": [ ... ],
    "scores": [ ... ]
  }
  ```
- 求人・評価軸が両方とも0件の場合はボタンが無効化される（エクスポートするデータがないため）
- `useCompareStore`（比較選択中の一時状態）はエクスポート対象に含まれない

### インポート

- 「JSONファイルを選択」ボタンからファイルピッカーを開き、`.json` ファイルを選択する
- 読み込みに成功すると、各ストアの state を上書きして「✓ インポートが完了しました」と表示する
- **現在のデータは確認なしに上書きされる**（インポート前にエクスポートでバックアップを取ることを推奨）
- 同じファイルを続けて再インポートできるよう、選択後にファイル入力をリセットする

#### バリデーション失敗ケース

| 状況 | エラーメッセージ |
|---|---|
| JSON として構文が不正（`JSON.parse` 失敗） | `JSON.parse` が投げる SyntaxError のメッセージをそのまま表示 |
| `version` フィールドが存在しない | `フォーマットが正しくありません` |
| `jobs` が配列でない | `フォーマットが正しくありません` |
| `criteria` が配列でない | `フォーマットが正しくありません` |
| `scores` が配列でない | `フォーマットが正しくありません` |

バリデーション失敗時はストアへの書き込みは行われない。エラーメッセージは赤背景で表示される。

### スコア計算方式（読み取り専用）

- 合致度スコアの計算式: `round(Σ(スコア × 重み) ÷ Σ(5 × 重み) × 100)`
- 未入力の評価軸はスコア0として計算される
- この画面での変更はできない（情報表示のみ）

### 全データリセット

- 「すべてのデータをリセット」ボタンを押すと `ConfirmModal` が開く
- モーダルには「求人 N件・評価軸 N件・評価 N件をすべて削除します。この操作は元に戻せません。」という件数付きの確認メッセージが表示される
- 「リセットする」ボタンで確定すると以下の処理が順に実行される:
  1. `useJobStore.setState({ jobs: [] })`
  2. `useCriteriaStore.setState({ criteria: [] })`
  3. `useScoreStore.setState({ scores: [] })`
  4. `useCompareStore.getState().clear()`
  5. `useCriteriaStore.getState().initDefaults()`（criteria が空になった直後に呼ぶため、デフォルト6軸が投入される）
- リセット後、アプリは「評価軸6軸のみ存在し、求人・評価がゼロ件」の初回起動状態と同等になる
- この操作は元に戻せない（undo 機能なし）

#### initDefaults が投入するデフォルト評価軸

| 名前 | 重み | 説明 |
|---|---|---|
| リモート | 3 | フルリモートなら5、出社必須なら1 |
| 年収 | 5 | 希望年収レンジに対して達成度を評価 |
| 技術スタック | 4 | 自分の強みと学びたい技術に合っているか |
| 裁量 | 3 | 設計・意思決定への関与度 |
| カルチャー | 3 | 企業文化・働き方が自分に合うか |
| 成長環境 | 4 | 学習機会・メンバーのレベル |
