# job-detail

## Overview

登録済み求人の全フィールドを閲覧し、応募ステータスをその場で変更できる詳細ページ。評価軸ごとのスコアサマリーを表示し、編集・削除へのエントリーポイントを提供する。

## Background

一覧画面では表示しきれない求人の詳細情報（福利厚生・スキル要件・メモなど）をひとつの画面に集約する。ステータス変更は転職活動中に頻繁に行う操作であるため、確認ダイアログを挟まずセレクタの変更と同時に即時保存する設計とした。

削除時のスコア連鎖削除をストア層ではなく UI 層の責務とした理由は、`useJobStore` と `useScoreStore` の間に直接依存を持ち込むとテストや将来の分割が困難になるためである（CLAUDE.md「連鎖削除のルール」参照）。

## User Stories

1. 求人の詳細情報（年収・勤務地・スキル要件など）を一覧画面から遷移して確認したい
2. 応募ステータス（書類選考中・面接中など）を画面遷移なしにその場で変更したい
3. 評価軸ごとのスコアと合致度スコアをサマリーとして確認したい
4. 未入力の評価軸がある場合にそれを視覚的に把握し、採点ページへ移動したい
5. 求人を削除するとき、関連する評価もまとめて削除されることを確認してから実行したい

## Behavior

### ページ表示条件

- URL パラメータ `id` に対応する求人が存在しない場合は「求人が見つかりません」メッセージを表示する。
- ページタイトル（`document.title`）は企業名（`companyName`）で更新される。

### ステータス変更セレクタ

- ヘッダー直下のサマリーカードに `<select>` を配置する。
- 選択値変更と同時に `updateJob` を呼び出して `useJobStore` へ即時反映する。
- 確認ダイアログは表示しない。
- 選択肢は `APPLICATION_STATUSES` 定数の列挙値をすべて表示する。

### 合致度スコアサマリー

| 条件 | 表示内容 |
|---|---|
| `weight > 0` の評価軸が 1 件以上存在し、スコアが 1 件以上入力済み | 合致度スコア（整数 %）を青字で表示 |
| `weight > 0` の評価軸がひとつもない | スコアサマリーを非表示 |
| 未入力の `weight > 0` 評価軸が 1 件以上ある | 合致度スコアの下に「未入力 N 軸あり」をオレンジ（amber）で表示 |

合致度スコアの計算式: `round(Σ(score × weight) / Σ(weight × 5) × 100)`

### 基本情報テーブル

| フィールド名 | 表示ラベル | 空値時の表示 |
|---|---|---|
| `source` / `sourceNote` | 媒体 | — |
| `salaryMin` / `salaryMax` | 年収 | — |
| `location` | 勤務地 | — |
| `remoteType` | リモート | — |
| `employmentType` | 雇用形態 | — |
| `workStartTime` | 始業時間 | — |
| `yearEndHolidays` | 年末年始休暇 | — |
| `annualBonus` | 賞与 | — |
| `housingAllowance` | 住宅補助 | — |
| `url` | 求人URL | 行ごと非表示 |

- 媒体表示: `source === 'その他'` かつ `sourceNote` が存在する場合は `sourceNote` の値を表示する。
- 年収表示: `salaryMin` または `salaryMax` の少なくとも一方が存在する場合に `?万〜?万円` 形式で表示。両方未入力の場合は `—`。
- 求人URL: 値が存在する場合のみ表示し、別タブで開く外部リンクとして表示する。

### スキル・技術セクション

- `requiredSkills`・`preferredSkills`・`techStack` がすべて空の場合、セクション自体を非表示にする。
- `requiredSkills`: 必須スキル（Tag コンポーネント、デフォルト色）
- `preferredSkills`: 歓迎スキル（Tag コンポーネント、デフォルト色）
- `techStack`: 技術スタック（Tag コンポーネント、blue バリアント）

### メモセクション

- `summary`（業務内容・要約）と `notes`（気になる点・懸念）の両方が空の場合、セクション自体を非表示にする。
- 各テキストは `whitespace-pre-wrap` で改行を保持して表示する。

### 評価サマリーセクション

評価軸（`criteria`）全件をリスト表示する。

| 状態 | 表示 |
|---|---|
| `weight === 0` の評価軸 | 軸名の右に「スコア対象外」バッジ（グレー）を表示 |
| スコア未入力（`score === 0` または Score レコードなし） | 右端に「未入力」をオレンジ（amber）で表示 |
| スコア入力済み | `ScoreWithLabel` コンポーネントで星と数値を表示 |
| `sc.memo` が存在する | スコア行の下にメモを小文字グレーで表示 |

評価軸が 1 件もない場合は「評価軸が設定されていません。」と表示する。

「評価を入力する」ボタンから `/jobs/:id/score`（ScoreInput ページ）へ遷移できる。

### 編集・削除

- **編集ボタン**: `/jobs/:id/edit` へ遷移する（`Pencil` アイコン付き ghost ボタン）。
- **削除ボタン**: `ConfirmModal` を開く（`Trash2` アイコン付き ghost ボタン、赤色スタイル）。
  - ConfirmModal のメッセージ: `「{companyName}」を削除します。この求人に入力した評価もすべて削除されます。`
  - 確認後の処理:
    1. `deleteScoresByJob(job.id)` で関連する Score レコードを全削除（連鎖削除）
    2. `deleteJob(job.id)` で求人を削除
    3. `/`（JobList）へ遷移

### 連鎖削除の設計方針

`useJobStore` と `useScoreStore` は互いを直接参照しない。Job 削除時に Score を削除する責務は JobDetail コンポーネント（UI 層）が担う。これによりストア同士の依存を排除し、各ストアを独立してテスト・分割できる。
